# RMK Battery Center

Плагин SwiftBar для macOS 12+, который читает заряд обеих половинок RMK-клавиатуры по Bluetooth. Небольшое Swift-приложение обращается к CoreBluetooth, а SwiftBar показывает результат в menu bar раз в минуту. Для OP36 с прошивкой Ergohaven используется её собственная команда чтения батарей; для других RMK-клавиатур поддерживаются стандартные Battery Service.

Пример: `⌨ Left 73% · Right 41%`. Заряд до 20% выделяется оранжевым. В меню доступны обновление и настройки Bluetooth. История заряда и уведомления пока не реализованы.

## Требования

- SwiftBar: [официальный репозиторий](https://github.com/swiftbar/SwiftBar), установка через `brew install swiftbar`.
- Swift 5.9+ для сборки; Xcode с принятой лицензией для XCTest.
- Клавиатура подключена к macOS по Bluetooth.
- Прошивка Ergohaven должна поддерживать Vial-запрос обеих батарей либо RMK должна публиковать отдельный Battery Service (`180F`) с Battery Level (`2A19`) для каждой половинки.

## Прошивка Ergohaven

В [форке Ergohaven](https://github.com/ergohaven/rmk/blob/main/rmk/src/host/via/mod.rs) есть команда `CustomGetValue` (`08 E8 01`, пакет 32 байта). Ответ содержит версию, флаги доступности и проценты левой и правой половинок. Программа использует только эту команду чтения и не изменяет раскладку или настройки клавиатуры.

На подключённой OP36 проверено получение обоих значений через установленный SwiftBar-плагин.

Поддерживаются vendor GATT service `8cfa65ff-3b6d-55f3-8b67-49693930420d` и Vial HID reports с Report Reference `[5, 1]` / `[5, 2]`. Запрос повторяется через две секунды после первого ответа, чтобы периферийная половинка успела обработать запрос обновления. Если этот протокол недоступен, программа читает стандартные Battery Service и сообщает об ограничении. Старые сборки Ergohaven могут не поддерживать команду.

Поддержку стандартного Battery Service для второй батареи добавили в [RMK #1038](https://github.com/rmk-rs/rmk/pull/1038). Это отдельный механизм от Vial-запроса Ergohaven. Старые прошивки могут отдавать только заряд центральной половинки. Программа не может восстановить отсутствующие в прошивке данные.

В [актуальной документации RMK](https://rmk.rs/main/docs/configuration/wireless) описаны настройки батарей. Схема конфигурации зависит от версии RMK. Не переноси ADC-пины или коэффициенты делителя с другой платы: используй значения из конфигурации OP36. Для peripheral должен быть настроен `battery_adc_pin`, непосредственно либо через preset платы. `battery_user_description` задаёт подпись батареи.

## Сборка и установка

Готовая сборка для Mac с Apple Silicon доступна в [GitHub Releases](https://github.com/akarmanov2022/rmk-battery-center/releases). Скачай архив `rmk-battery-center-v0.1.0-macos-arm64.zip`, распакуй его, открой Terminal в распакованной папке и запусти:

```sh
./scripts/install.sh "/полный/путь/к/папке/плагинов/SwiftBar"
```

Для готовой сборки Xcode не нужен. Приложение подписано ad hoc, без Developer ID и нотариального заверения Apple; macOS может потребовать разрешить его запуск в настройках безопасности.

Для сборки из исходников, в том числе на Intel Mac:

```sh
./scripts/build.sh
./scripts/install.sh "/полный/путь/к/папке/плагинов/SwiftBar"
```

Путь к папке плагинов можно посмотреть в настройках SwiftBar. Указывай именно эту папку; не добавляй в SwiftBar весь репозиторий. Установка копирует приложение в `~/Library/Application Support/RMK Battery Center/`, а в папку плагинов — только `rmk-battery.1m.sh`.

При первом обновлении macOS запросит доступ к Bluetooth для RMK Battery Center. Разреши его. Если первый запрос занял больше 20 секунд, нажми Refresh после выдачи разрешения. Приложение подписано локальной ad hoc подписью, без Developer ID; после пересборки macOS может запросить доступ повторно.

Если Bluetooth-имя клавиатуры отличается от `OP36`, запиши точное имя в файл:

```sh
printf '%s\n' 'Имя клавиатуры' > "$HOME/Library/Application Support/RMK Battery Center/name"
```

Если подключены две клавиатуры с одинаковым именем, можно записать CoreBluetooth UUID нужной клавиатуры в файл `identifier` в той же папке. Это UUID macOS, а не Bluetooth MAC-адрес; непустой identifier имеет приоритет над именем.

Названия половинок хранятся в файлах `left-name` и `right-name` в той же папке. Например, для коротких подписей:

```sh
printf '%s\n' 'L' > "$HOME/Library/Application Support/RMK Battery Center/left-name"
printf '%s\n' 'R' > "$HOME/Library/Application Support/RMK Battery Center/right-name"
```

Нажми Refresh в меню плагина или дождись следующего обновления. Без этих файлов используются `Left` и `Right`. Установка обновлений сохраняет заданные имена. Настройка заменяет подписи `Left` и `Right` из протокола Ergohaven или описаний стандартных сервисов; нейтральные `Battery 1` и `Battery 2` остаются без изменений, поскольку их физическая сторона неизвестна. Для проверки можно запустить помощник с `--demo --left-name L --right-name R`.

## Проверка без клавиатуры

```sh
./dist/"RMK Battery Center.app"/Contents/MacOS/rmk-battery --demo
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
```

`--demo` выводит явно помеченные тестовые значения и не обращается к Bluetooth.

## Поведение и диагностика

- Программа читает уже подключённые устройства, не запускает поиск и не выполняет сопряжение. Если устройство не найдено, проверь подключение, имя и пробуждение клавиатуры.
- В протоколе Ergohaven прошивка передаёт значения в физическом порядке Left/Right. При чтении стандартных Battery Service каждая копия обрабатывается отдельно, даже если UUID одинаковые. Имена берутся из User Description (`2901`); без описания показаны нейтральные `Battery 1`, `Battery 2`. Порядок сервисов не доказывает, где левая половинка.
- `—` означает отсутствие корректного значения, а `0%` — реально полученный нулевой заряд. Неизвестные и просроченные значения не подменяются кешем.
- Если прошивка публикует только одну батарею, меню сообщает об этом. Для проверки поддержки второй нужна версия или репозиторий прошивки OP36.
- Чтение ограничено 12 секундами; плагин ожидает результат до 20 секунд. Показания обновляются раз в минуту, по данным, которые предоставляет прошивка. Возраст измерения внутри прошивки определить невозможно.
- При отказе в доступе включи RMK Battery Center в System Settings → Privacy & Security → Bluetooth.
- Работа через USB или USB-донгл не реализована.
